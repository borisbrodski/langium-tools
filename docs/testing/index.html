langium-tools/testing

Generator tests

Generated code is part of the contract. Commit it. The test builds a real Langium workspace, runs your generator in memory, and checks every file. When you mean to change the output, regenerate and review the diff.

Two modes

  • Verify — the default. In-memory output must match the committed files, byte for byte, and the overwrite flags must match the metadata.
  • Generate — GENERATOR_TEST=generate. The generated/ directory is replaced and the metadata file is rewritten.
package.json 
{
  "scripts": {
    "test": "vitest run",
    "test:generate": "GENERATOR_TEST=generate vitest run"
  }
}

npm test is what CI runs. npm run test:generate is what you run locally after an intentional generator change. Then git diff and commit.

One test per workspace

langiumGeneratorSuite adds a Vitest test for each immediate subdirectory. createServices receives NodeFileSystem from langium/node. When you use generateForModel, the service object must have exactly one entry besides shared. That is the usual Langium shape: { MyDsl, shared }.

generator.test.ts 
import { langiumGeneratorSuite } from 'langium-tools/testing';
import { createMyDslServices } from '../src/language/my-dsl-module';

langiumGeneratorSuite('./test-workspaces', {
  createServices: (context) => createMyDslServices(context),
  generateForModel: async (_services, model, gen) => {
    gen.createFile('out/' + model.name + '.ts', render(model));
  },
});

Directory layout

Put DSL files in dsls/. The runner looks for that name before it deletes anything, so a wrong path cannot wipe an unrelated folder. Generated files land in generated/. With the default target, metadata is generated-metadata.json next to dsls/.

test-workspaces 
test-workspaces/
  lights/
    dsls/
      room.mydsl
    generated/
      out/Room.ts
    generated-metadata.json
  doors/
    dsls/
      door.mydsl
    generated/
      out/Door.ts
    generated-metadata.json

What the default pipeline does

  1. initWorkspace — WorkspaceManager.initializeWorkspace on the test directory.
  2. buildDocuments — every document Langium loaded, built with validation on.
  3. validateDocuments — fails the test if the DSL has lexer or parser errors. Validation diagnostics are not treated as failures here, so a workspace can legally contain warnings.
  4. generate — generateForModel for each document, or your own generateForWorkspace if generation is not one-file-at-a-time.
  5. compare or write — verify mode reads the tree. Generate mode replaces it.

Any of those steps can be replaced on the options object.

A single workspace, from any test runner

langiumGeneratorTest does not call Vitest's test(). Use it when you want one workspace inside a test you wrote yourself. The assertions still use Vitest's expect. using, from the same entry, runs a function with a value and returns that value.

one-workspace.test.ts 
import { GeneratorMode, langiumGeneratorTest } from 'langium-tools/testing';

await langiumGeneratorTest('./test-workspaces/lights', {
  createServices: (context) => createMyDslServices(context),
  generateForModel: async (_services, model, gen) => {
    gen.createFile('out/' + model.name + '.ts', render(model));
  },
  generateMode: GeneratorMode.Verify,
});

Custom targets and stricter validation

Pass targets as the third argument. Once any target is passed, every target is written that way, including the default one: generated/DEFAULT/ with DEFAULT-metadata.json, and generated/<name>/ with <name>-metadata.json. With no extra targets, files stay in generated/ and the metadata file is generated-metadata.json. The check fails when a file is missing, unexpected, different, or when its overwrite flag changed.

java-target.test.ts 
import { getDocumentIssueSummary } from 'langium-tools/base';

function validateDocuments(services, documents) {
  for (const doc of documents) {
    const summary = getDocumentIssueSummary(doc);
    expect(summary.countErrors, summary.message).toBe(0);
  }
}

langiumGeneratorSuite('./test-workspaces', {
  createServices: (context) => createMyDslServices(context),
  validateDocuments,
  generateForModel: async (_services, model, gen) => {
    gen.createFile('out/' + model.name + '.java', renderJava(model), { target: 'java' });
    gen.createFile('src/' + model.name + '.java', stub(model), { target: 'java', overwrite: false });
  },
}, [
  { name: 'java', overwrite: true },
]);

Metadata

The JSON is how a change from "generate once" to "always overwrite" shows up in review even when the file bytes stayed the same.

generated-metadata.json 
{
  "generatedFiles": [
    { "filename": "out/Room.ts", "overwrite": true },
    { "filename": "src/Room.ts", "overwrite": false }
  ]
}

Verify mode never writes. A failing test leaves the committed tree as it was, and the message names the file, the target, and whether the mismatch is content, a missing file, an extra file, or the overwrite flag.

API: langiumGeneratorSuite, langiumGeneratorTest, GeneratorTestOptions.
