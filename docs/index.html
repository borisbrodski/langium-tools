The work around the grammar, already built.

Langium parses, links, validates, and speaks LSP. A real DSL project still needs three more things: one way to see every error, a generator that does not thrash the filesystem, and tests that pin both. langium-tools is that layer.

Why this library

Stop rebuilding the same three tools

Every Langium grammar eventually grows a CLI, a generator, and a test suite. Those pieces look different in every repository, and they drift. This library is the shared version, with tests of its own.

One list of problems

Lexer errors, parser errors, and validation diagnostics live on different objects, with different position conventions. A CLI that prints only document.diagnostics hides syntax errors. getDocumentIssues returns all three, and getDocumentIssueSummary prints them.

Generators that leave quiet files alone

Writing every file on every run changes timestamps and wakes every watcher downstream. Generated content is collected in memory first. A file is rewritten only when the bytes differ and overwrite is allowed. Initial files can be generated once and then left for the user to edit.

Snapshot tests for a tree of files

A single expected string falls apart once a generator emits dozens of files. Commit the generated/ directory. The test builds the workspace, generates in memory, and compares content and the overwrite flag. A real change is approved by regenerating and reading the git diff.

Markers instead of column arithmetic

Hard-coded line and column numbers break as soon as the sample DSL gains a line. Wrap the offending name in a marker, parse with parseWithMarks, and assert the issue sits on that span. The markers are stripped before Langium sees the text.

Several output trees, one generator

A language often emits a generated tree and a second tree of files the user is allowed to edit. Targets carry their own default overwrite flag. The same relative path can be produced twice, into two directories, without a second code path.

Java files with honest imports

Package declaration, import list, and body are assembled after the body has asked for every class it uses. Two types named List do not both become a short name. The collision keeps the fully qualified form.

Where it fits

Langium still owns the language

You keep your grammar, your services, and your language server. langium-tools reads documents Langium already built, and it writes files your generator decides on.

  1. DSL textfiles in a workspace, or a string in a test
  2. Langiumlex, parse, link, validate
  3. Your generatorwalk the AST, decide the files
  4. Diskonly the files that actually changed
Issues read the document after parsing and validation.
Matchers assert those issues, optionally on a marker in the sample.
GeneratedContentManager sits between the generator and the disk.
langiumGeneratorSuite runs the whole path and compares the tree.
Getting started

Install it next to Langium

The package is ESM. Imports are subpaths, so a project that only checks diagnostics does not pull in the generator. The testing entry registers Vitest matchers and expects Vitest 2.

terminal 
npm install langium-tools

Fail the CLI when the document is wrong

cli.ts 
import { getDocumentIssueSummary } from 'langium-tools/base';

const summary = getDocumentIssueSummary(document);
if (summary.countErrors > 0) {
  console.error(summary.message);
  process.exit(1);
}

Generate, then write

generator.ts 
import { GeneratedContentManager } from 'langium-tools/generator';

const manager = new GeneratedContentManager();

function generate(model: Model) {
  const gen = manager.generatorManagerFor(model);
  gen.createFile('src-gen/model.ts', `// generated\nexport const name = '${model.name}';\n`);
  gen.createFile('src/model.ts', `export const name = '${model.name}';\n`, { overwrite: false });
}

for (const model of models) generate(model);
await manager.writeToDisk('./generated');

Lock the generator output in CI

Default mode compares against the committed tree. Set GENERATOR_TEST=generate when you intend to update it.

generator.test.ts 
import { langiumGeneratorSuite } from 'langium-tools/testing';

langiumGeneratorSuite('./test-workspaces', {
  createServices: (context) => createMyDslServices(context),
  generateForModel: async (_services, model, gen) => {
    gen.createFile('out/' + model.name + '.ts', render(model));
  },
});
