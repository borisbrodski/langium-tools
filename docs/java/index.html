langium-tools/lang/java

Java files

The awkward part of generating Java is the import block: it has to be written before the class, but you only know which types the body used afterwards, and two classes can share a simple name. generateJavaFile does that bookkeeping and hands the file to a GeneratorManager.

One function for a whole file

The body is a Langium CompositeGeneratorNode. Call the function you are given with a fully qualified name every time the body mentions a class. It returns the text that should appear at that spot: the simple name, or the full name when the simple name is already taken.

door.ts 
import { expandToNode } from 'langium/generate';
import { generateJavaFile } from 'langium-tools/lang/java';

generateJavaFile(
  'Door',
  'com.example.sm',
  gen,
  (imp) => expandToNode`
    public class Door {
      private final ${imp('java.util.List')}<String> names;
      private final ${imp('java.awt.List')} peer;

      public Door(${imp('java.util.List')}<String> names) {
        this.names = names;
      }
    }
  `,
);

The file written for package com.example.sm is:

com/example/sm/Door.java 
package com.example.sm;

import java.util.List;

public class Door {
  private final List<String> names;
  private final java.awt.List peer;

  public Door(List<String> names) {
    this.names = names;
  }
}

java.util.List was registered first, so it owns the name List. java.awt.List stays qualified and is not imported. The path is com/example/sm/Door.java, relative to the generator target. An optional last argument is the usual CreateFileOptions (overwrite, target).

Imports on their own

JavaImportManager is what generateJavaFile uses. Construct it with the package of the file being generated. Classes in that package are not imported. generateImports returns the import statements, sorted, separated by the platform newline. Call useClass while building the body, and generateImports after the body is done. The import block is empty when nothing outside the current package was used.

imports.ts 
import { JavaImportManager } from 'langium-tools/lang/java';

const imports = new JavaImportManager('com.example.sm');

imports.useClass('java.util.List');     // "List", and an import
imports.useClass('java.awt.List');       // "java.awt.List", no second import
imports.useClass('com.example.sm.Door'); // "Door", same package, no import

imports.generateImports();
// import java.util.List;

Package to directory

path.ts 
import { packageToPath } from 'langium-tools/lang/java';

packageToPath('com.example.sm'); // "com/example/sm"

java.lang is not special-cased yet. Passing java.lang.String produces an import. Prefer to write String in the body and not register it.

API: generateJavaFile, JavaImportManager, packageToPath.
