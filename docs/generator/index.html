langium-tools/generator

Code generation

A generator should decide the files. The filesystem should be a later step. GeneratedContentManager collects every file in memory, from as many models as you have, and writes them when you ask.

Why keep it in memory

  • Tests compare the map of files. They do not need a temp directory for the happy path.
  • Two models that emit the same path with different text fail immediately, with both document paths in the error.
  • Unchanged files are not rewritten, so timestamps stay put and file watchers stay quiet.
  • A file marked overwrite: false is created if it is missing and left alone if someone has edited it.

The usual shape

One manager for the run. One GeneratorManager per model. createFile records a path relative to the output directory.

generate.ts 
import {
  GeneratedContentManager,
  type GeneratorManager,
} from 'langium-tools/generator';

const manager = new GeneratedContentManager();

function generate(gen: GeneratorManager<Model>) {
  const model = gen.getModel();
  gen.createFile(
    'src-gen/' + model.name + '.ts',
    '// Generated. Do not edit.\nexport const name = ' + JSON.stringify(model.name) + ';\n',
  );
  gen.createFile(
    'src/' + model.name + '.ts',
    'export const name = ' + JSON.stringify(model.name) + ';\n',
    { overwrite: false },
  );
}

for (const model of models) {
  generate(manager.generatorManagerFor(model));
}

await manager.writeToDisk('./generated');

What the generator can see

The manager hangs off the AST node. If that node was parsed by Langium, $document is set and the helpers below resolve.

context.ts 
function generate(gen: GeneratorManager) {
  const model = gen.getModel();
  const document = gen.getDocument();          // LangiumDocument, if the AST was parsed
  const workspace = gen.getWorkspaceURI();     // which workspace folder contains it
  const localPath = gen.getDocumentLocalPath(); // path inside that folder, '/' separators
}

Pass workspace directory URIs into the constructor when a document should be described by a path inside a workspace rather than by its full URI. getDocumentLocalPath uses / on every platform. If the file sits in none of the workspaces, you get the basename.

workspaces.ts 
const manager = new GeneratedContentManager([
  'file:///workspace/app',
  'file:///workspace/lib',
]);

Overwrite

The default target is named DEFAULT and overwrites. Pass { overwrite: false } for a file that should exist after the first generation and then belong to the user. On disk the rule is:

  • Missing file: write it.
  • Existing file, same bytes: do nothing. The timestamp does not change.
  • Existing file, different bytes, overwrite true: replace it.
  • Existing file, different bytes, overwrite false: leave the user's file.

Recording the same path twice with different content, or with a different overwrite flag, throws. Generating the same bytes twice is allowed.

Targets

A target is a named output tree with its own default overwrite flag. This is the same idea as an Xtext outlet: generated sources in one directory, once-only stubs in another. The path you pass to createFile is relative to whichever directory you later pass to writeToDisk.

targets.ts 
manager.addTarget({ name: 'once', overwrite: false });

gen.createFile('Model.ts', generated, { target: 'once' });
gen.createFile('Model.ts', generated); // default target, overwrite true

await manager.writeToDisk('./src-gen');          // default target
await manager.writeToDisk('./src', 'once');      // the "once" target

Cleaning the output directory

writeToDisk does not delete leftovers. cleanAndWriteToDisk writes first, then removes files in that directory that were not part of this generation. Files whose content did not change are not deleted and recreated.

clean.ts 
// Delete files in the output directory that this generation did not produce.
await manager.cleanAndWriteToDisk('./src-gen');

// Same thing, explicit:
await manager.writeToDisk('./src-gen', undefined, true);

The generator test runner uses this manager. In verify mode it never writes. It compares the in-memory map to the committed tree, including the overwrite flag stored in the metadata JSON. See the generator tests guide.

Types: GeneratedContentManager, GeneratorManager, CreateFileOptions.
