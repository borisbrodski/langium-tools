langium-tools/testing

Vitest matchers

Importing langium-tools/testing adds four matchers to Vitest. They assert the same document issues you print in a CLI, so a test and a log cannot disagree about what an error is.

Setup

The import is a side effect: it calls expect.extend. Parsing stays Langium's parseHelper. The matchers are written for Vitest 2, which is a peer dependency.

setup.ts 
import 'langium-tools/testing'; // registers the matchers
import { EmptyFileSystem } from 'langium';
import { parseHelper } from 'langium/test';
import { adjusted } from 'langium-tools/base';
import { parseWithMarks } from 'langium-tools/testing';

const services = createMyDslServices(EmptyFileSystem);
const parse = parseHelper(services.MyDsl);

No errors, no issues

toHaveNoErrors ignores warnings, information, and hints. toHaveNoIssues does not. Both accept a LangiumDocument or the object returned by parseWithMarks. A failure prints the issue summary.

clean.test.ts 
const document = await parse('statemachine Door\n', { validation: true });

expect(document).toHaveNoErrors();  // warnings are ignored
expect(document).toHaveNoIssues();  // warnings, hints, and errors all count

Put the location in the sample

parseWithMarks strips a begin/end pair, parses the remaining text with validation on, and remembers where each marker was. The default pair is <<{| and |}>>. Pick a pair that cannot appear in the DSL. Markers are numbered from 0 in the order they occur. adjusted removes the indent of the template so line 1 of the DSL is the first line of content.

marked.test.ts 
import { DocumentIssueSeverity, DocumentIssueSource } from 'langium-tools/base';

const parsed = await parseWithMarks(
  parse,
  adjusted`
    statemachine Door
    state [[[Unused]]];
  `,
  '[[[',
  ']]]',
);

expect(parsed).toHaveDocumentIssues([
  {
    source: DocumentIssueSource.VALIDATION,
    severity: DocumentIssueSeverity.WARNING,
    message: 'This state is declared but never referenced.',
    markerId: 0,
  },
]);

An IssueExpectation has:

  • message — a string, or a regular expression. Required.
  • severity — defaults to ERROR.
  • source — LEXER, PARSER, or VALIDATION. Omitted means "do not care".
  • markerId — 0-based index. Omitted means "do not care where".

toHaveDocumentIssues matches each expectation to one actual issue and fails if anything is left over on either side. The message lists the unmatched expected issues and the unmatched actual ones.

One issue among others

toContainIssue succeeds when at least one issue matches. Extra issues are fine. Pass a parsed document with markers if the expectation has a markerId.

contain.test.ts 
import { DocumentIssueSeverity, DocumentIssueSource } from 'langium-tools/base';

expect(document).toContainIssue({
  message: /Unexpected character/,
  severity: DocumentIssueSeverity.ERROR,
  source: DocumentIssueSource.LEXER,
});

Ignore a class of issues

Every matcher takes IgnoreParameters: ignoreParserErrors, ignoreLexerErrors, ignoreValidationErrors, ignoreNonErrorDiagnostics. The last one defaults to true only for toHaveNoErrors.

ignore.test.ts 
import { DocumentIssueSeverity } from 'langium-tools/base';

expect(document).toHaveNoErrors({ ignoreLexerErrors: true });

expect(parsed).toHaveDocumentIssues(
  [{ message: 'This state is declared but never referenced.', severity: DocumentIssueSeverity.WARNING }],
  { ignoreValidationErrors: true },
);

A marker comparison uses the positions the issue actually has. Lexer and parser issues often have a start and no end. Validation issues have a start and an end. A zero-length marker is a point: start and end offsets are equal.

API: toHaveNoErrors, toHaveNoIssues, toHaveDocumentIssues, toContainIssue, parseWithMarks.
