Text helpers

Small functions that show up in every generator and every test. They live next to document issues on langium-tools/base.

Templates that keep their indent

adjusted is Langium's expandToNode plus toString. A substituted value is re-indented to the column of the placeholder, which is what you want when the value is itself a block of code. Newlines follow the platform. adjustedUnix is the same text with \r removed, so a snapshot does not depend on the operating system.

template.ts 
import { adjusted, adjustedUnix } from 'langium-tools/base';

const cmds = 'console.log("Hello,");\nconsole.log("World!");';

const text = adjusted`
  ${cmds}
  if (sayAgain) {
    ${cmds}
  }
`;

The value of text:

output 
console.log("Hello,");
console.log("World!");
if (sayAgain) {
  console.log("Hello,");
  console.log("World!");
}

The leading indent of the whole template is removed. A line that is only whitespace disappears. That is why multi-line samples in the matcher guide start at column 0.

First letter

undefined stays undefined, which matters when a name in the AST is optional. Importing the module patches String.prototype with toFirstUpper and toFirstLower. The functions do not change the rest of the string.

case.ts 
import { toFirstUpper, toFirstLower } from 'langium-tools/base';

toFirstUpper('door'); // "Door"
toFirstLower('Door'); // "door"

// Importing the module also adds the methods on String:
'door'.toFirstUpper();
'Door'.toFirstLower();

Sort in place

arraySortBy sorts the array you pass and returns it. The key is a property name or a function. Numbers use subtraction, strings use localeCompare, and null and undefined go last. Importing the module adds sortBy on Array.

sort.ts 
import { arraySortBy } from 'langium-tools/base';

const people = [
  { name: 'Ada', size: 2 },
  { name: 'Max', size: 1 },
];
arraySortBy(people, (p) => p.name);
arraySortBy(people, 'size');

// or, after importing the module:
people.sortBy((p) => p.name);

Markers

parseMarkedText removes paired markers and records where they were. parseWithMarks is this function followed by a Langium parse. Use the parser directly when you only need the positions, for a generator test or a editor fixture. The default markers are <<{| and |}>>. A marker with nothing between the ends is a point: the start offset equals the end offset.

markers.ts 
import { parseMarkedText } from 'langium-tools/base';

const { text, markers } = parseMarkedText(
  'state [[[Open]]] [[[Close]]]',
  '[[[',
  ']]]',
);
// text === 'state Open Close'
// markers[0] covers "Open", markers[1] covers "Close"
// offsets, lines, and columns are 0-based
// endOffset / endColumn point at the character after the span

The prototype methods are installed when langium-tools/base is loaded. Named imports run the same patches. That is part of the base API.

API: adjusted, adjustedUnix, toFirstUpper, arraySortBy, parseMarkedText.
